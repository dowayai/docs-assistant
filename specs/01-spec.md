# Специфікація v0.1 — асистент до технічної документації

## Користувачі і сценарії
- U1: розробник шукає відповідь на питання щодо документації бібліотеки/проєкту.
- U2: користувач завантажує власні документи й ставить до них питання.

## Функційні вимоги
| ID | Вимога | Критерії приймання (AC) | Перевірка |
|---|---|---|---|
| FR-01 | Індексація документів Markdown, TXT, PDF | AC1: файл підтримуваного формату потрапляє до індексу; AC2: непідтримуваний формат дає зрозумілу помилку | tests/test_ingest.py |
| FR-02 | Поділ на фрагменти зі збереженням структури | AC1: фрагмент не перевищує `CHUNK_MAX_CHARS`; AC2: кожен фрагмент має метадані `source`, `section` | tests/test_ingest.py |
| FR-03 | Ембедінги багатомовною моделлю | AC1: та сама модель для документів і питань | перегляд коду, `src/store.py` |
| FR-04 | Зберігання у векторній базі з метаданими | AC1: після перезапуску індекс доступний | ручний сценарій |
| FR-05 | Пошук top-k фрагментів за питанням | AC1: повертає ≤ k фрагментів з відстанню й метаданими | eval/ (Recall@k) |
| FR-06 | Відповідь LLM на основі контексту з цитуванням | AC1: відповідь містить посилання [n] на надані фрагменти | eval/ (citation correctness) |
| FR-07 | Відмова за відсутності підстав | AC1: якщо релевантних фрагментів немає, LLM не викликається, повертається фіксоване повідомлення | tests/test_rag.py, eval/ (питання поза межами) |
| FR-08 | Інтерфейс Streamlit: завантаження, питання, відповідь, джерела | AC1: джерела видно разом із відповіддю | ручний сценарій |
| FR-09 | Оцінка відповіді користувачем | AC1: оцінка записується у `data/feedback.jsonl` | ручний сценарій |

## Нефункційні вимоги
- NFR-01: параметри (модель ембедінгів, LLM, k, поріг відстані) конфігуруються без зміни коду.
- NFR-02: повторна індексація тих самих файлів не дублює фрагменти.
- NFR-03: час відповіді фіксується у логах для аналізу (розділ 6).
